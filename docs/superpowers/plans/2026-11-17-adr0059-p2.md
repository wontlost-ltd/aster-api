# ADR 0059 P2：B 形态策略包导出——实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 用户在策略详情页把**已批准版本**导出为 B 形态（源码 + 元数据）的签名策略包（JRE 与 Node 两种 target），用 P1 已实现的通用 CLI（`java -jar aster-cli-<ver>.jar` / npm `aster`）在平台外编译并运行；aster-api 负责编译、导出检查、探针、组装可复现 zip、专用导出密钥签名、JWKS 与审计，aster-cloud 负责计划门、Node 侧探针与重编译比对、下载代理与 UI。

**Architecture:** aster-api 新包 `io.aster.policy.export` 以生产编译路径（`PolicyCompiler`）取 Core IR，在 IR 上做导出检查（E730–E733、E737、E738，白名单读 P1 T10 的生成文件），按 Core IR 类型生成 `schema/input.json` / `output.json` 与探针，经 `/evaluate-json` 同一执行路径算出期望值，组装 manifest（规范 JSON 字节）、`SHA256SUMS`、README 与确定性 zip，用导出密钥 Ed25519 签名；三个端点 `check` / `prepare` / `export/package` 只接受 cloud 的 HMAC 调用。cloud 在 Worker 内用自身依赖的 ts 编译器与解释器复核 Node 包（E735、E739），再把 zip 字节原样转发给浏览器。依赖 P1 引擎代码（core / truffle embed、ts `./package-check`、错误码登记）的任务集中在列车 eco-1.0.50 与 ts ≥ 3.3.0 之后；其余任务现在就能做，两仓各自以开关保持生产关闭。

**Tech Stack:** aster-api：Java 25、Quarkus、Flyway、Hibernate Panache、Jackson、JDK `EdDSA` / `java.util.zip`、JUnit 5 + `@QuarkusTest`、networknt json-schema-validator（测试）。aster-cloud：Next.js on Cloudflare Workers（OpenNext，`nodejs_compat`）、Drizzle（本计划不改 schema）、vitest、Playwright + axe、next-intl（`src/i18n/demo-supplement.ts`）。aster-lang-ts：TypeScript、`node --test`。aster-dev：Next.js + MDX。k3s：ExternalSecret（ESO，Vault）。

## Global Constraints

- **只导出 APPROVED 版本**：cloud 用 `findDefaultExecutableVersion`，无可执行版本 409 `{ error: 'no executable version' }`（同 Cedar）；aster-api 不接受草稿。
- **v1 只做 B**：`mode` 只接受 `"b"`，其他值 400 `mode_unsupported`（A 是 P3）。`target` ∈ `node` / `jre`。
- **鉴权**：三个包端点只接受 HMAC 已验签的内部调用（cloud）；API Key 调用方 403 `export_requires_cloud`（修订 3 P2-R10）。
- **开关**：aster-api `aster.export.package.enabled`（env `ASTER_EXPORT_PACKAGE_ENABLED`，缺省 `false`，关时三个包端点 404）；cloud PlatformSetting `policy_export.package.enabled`（缺行 `false`）。JWKS 端点不受开关影响（`keys:[]` 也照常返回）。
- **计划门**：`PlanCapabilities.policyExport`：free = `false`；trial / pro / team / enterprise = `true`；套餐持有人 = `planHolderForTeam(userId, policy.teamId)`；不满足 403 `{ error: 'policy_export_requires_plan', upgrade: true }`。Cedar 导出不门控、不改。
- **导出密钥**：`aster.export.signing-keys` / `aster.export.active-kid`（env `ASTER_EXPORT_SIGNING_KEYS` / `ASTER_EXPORT_ACTIVE_KID`）；JSON 形状与收据密钥相同 `{"revision":N,"keys":[{"kid","privateKey","notAfter"?,"revoked"?}]}`；配置畸形 → 启动失败（消息不含种子）；缺配置 → 导出 503 `export_signing_unavailable`；`aster.export.package.allow-unsigned`（缺省 `false`，仅 on-prem）为 true 时缺配置改为无签名导出；`active-kid` ∉ 该 target 的锁文件 `trustAnchorKids` → 503 `export_signing_kid_unanchored`。kid 不得以 `test-` 开头（conformance `keys/README.md` M4）。
- **JWKS**：`GET /api/v1/exports/keys`（匿名可读），形状与 `/api/v1/guard/keys` 相同（`{keys:[{alg:"EdDSA",crv:"Ed25519",kid,kty:"OKP",use:"sig",x[,exp]}],revision}`，`Cache-Control: max-age=300`）。
- **锁文件** `src/main/resources/export/export-runtimes.lock.json`：`{"formatVersion":1,"jre":{"cliName":"cloud.aster-lang:aster-cli","cliVersion":…,"trustAnchorKids":[…]},"node":null|{"cliName":"@aster-cloud/aster-lang-ts","cliVersion":…,"trustAnchorKids":[…]}}`；首个提交为 `jre.cliVersion = "1.0.49"`、`trustAnchorKids: []`、`node: null`（因此生产在列车与密钥就绪前必然 503，fail-closed）。
- **manifest 固定值**：`format` `"aster-policy-package"`、`formatVersion` `"1.0"`、`coreIr.version` `2`、`effects.io` `false`、`governance.enforced` `false`、`exportedBy.issuer` `"aster-cloud"`、`exportedBy.tenantId` = 已验证租户；`runtime.engine`：jre `aster-lang-truffle` / node `aster-lang-ts-interpreter`；`runtime.requires`：jre `{"java":">=25"}` / node `{"node":">=24"}`；`runtime.ecosystem` = aster-api 构建时的 `asterLang` 目录版本；`runtime.cli` = 锁文件该 target 的 `{name: cliName, version: cliVersion}`（B 无 `sha256`）。其余字段推导与 `fixtures.mjs` `buildPackage` 相同（`effects.declared` 为各函数效果的排序并集，`governance.verdict` 为入口返回 Verdict，`policy.controls` 为入口 `@control` 排序，`ruleId` 为入口 `@id`，`profile` 为 `ir.profile ?? null`，`governance.factSources` 为档案声明的事实来源排序）。
- **文件集合**（B）：`README.md`、`policy/policy.aster`（源码 UTF-8 字节不变）、`policy/compile/alias-set.json`（规范 JSON；无 aliasSet 写 4 字节 `null`）、`policy/compile/vocabulary.json`（规范 JSON；无词汇则**不写此文件**）、`schema/input.json`、`schema/output.json`、`tests/probes.json`，外加 `manifest.json`（规范 JSON 字节）、`manifest.sig.json`（规范 JSON；无签名导出时缺省）、`SHA256SUMS`（GNU `<hex>␠␠<path>\n`，载荷 + `manifest.json`，按路径 UTF-8 字节序）。
- **zip**：`ZipOutputStream`；只有文件条目；条目名 `<root>/<path>`，`<root>` = `<moduleName>-v<claimedRef.version>-<target>-b`；按路径 UTF-8 字节序；`setTimeLocal(LocalDateTime.of(1980,1,1,0,0))`；`DEFLATED`，`Deflater` 级别 9；无 extra field、无注释（修订 3 P2-R14）。
- **上限**：整个 zip ≤ 1 MiB（`1_048_576` 字节），超出 E734（诊断给实际大小与上限）；探针 ≤ 256；源码长度沿用 `CnlSourceLimits.MAX_ANON_SOURCE_LENGTH`；aliasSet / 词汇沿用 `validateAliasSetBounds` / `VocabularyBounds`。
- **并发与限流**：aster-api `aster.export.package.max-concurrent`（缺省 `2`）作用于 `prepare` 与 `export/package`，占满 503 `package_export_busy` + `Retry-After: 1`；cloud 限流 `checkRateLimit(\`policy-package-export:${userId}\`, RateLimitPresets.EVALUATE_SOURCE)`。
- **错误码**：E730 IO 能力、E731 workflow / Async / Await、E732 名字不在闭世界、E733 入口类型无 JSON Schema、E734 超限、E735 Node 探针不一致、E737 入口被 `main` 抢占、E738 入口类型含 DateTime / PII、**E739 Node 重编译漂移**（修订 3 P2-R5）；E736 保留不启用。英文 message 模板见 T8；登记位置见 T21。

- **cloud 迁移拆分**：`drizzle/*.sql` 只在只含迁移的 PR 中出现，迁移在生产确认应用后才合代码 PR。**本计划不改 cloud schema**（修订 3 P2-R17，已核：无新表、无新 `UsageType`）。aster-api 同理：V6.40.0 单独一个 PR，部署确认后才合用它的代码。

## Review Focus

1. **同一输入导出两次，zip 逐字节相同**；而 envelope、`claimedRef`、target、锁文件版本、`probesSha256`、`nodeCheck`、任一载荷改变，manifest 哈希必变（ADR §6.1 两条测试）。导出时间、请求 id、JVM 默认时区都不得进入字节——T11 在 `TZ=Pacific/Kiritimati` 与 `UTC` 两种时区下各导出一次比较。
2. **平台导出的包必须被两个 P1 CLI 接受**：aster-api 产出的每个 B 包对 `aster verify --probes` 返回 `ok:true`，`run` 每条探针输入的信封值与 `tests/probes.json` 期望逐字节相同。中文模块名（`块.遮蔽`）、de 词汇、非空 aliasSet、Decimal 字段、超出 2⁵³ 的 Long 结果都要覆盖。T11 用 JSON Schema 与参照检查先守住，T15 列车后用 jre CLI 实跑。
3. **缺密钥 / kid 未进锚 / 锁文件 node 为 null / cloud ts 版本漂移**：每种都必须在组装 zip 之前失败，返回各自的 503 码，且不写审计；UI 不能因此显示「导出成功」。T4、T12、T13、T23 各有测试。
4. **探针中的非整数 Decimal 与字符串 Long**：平台期望值必须按声明类型求值（#558），否则 Node 比对必然 E735、黄金门必然失败。T5 覆盖嵌套 Data 字段与 List 元素；T9 断言生成的 Decimal 探针在平台上不报 `Cannot combine Decimal and Double`。
5. **伪造的 `nodeProbes`**：cloud 提交的 `probesSha256` 与 aster-api 重算不同、`agreed < count`、`tsVersion` 与锁文件不同、或 `target=jre` 却带 `nodeProbes`，都 400 拒绝，不签名（T13）。
