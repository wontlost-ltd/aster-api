# ADR 0058 阶段 1（能力授权 + 编辑器）实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让平台管理员能整体开关「Structured Authoring / 结构化编写」，并按用户、按团队授予（团队 owner 可在座位内委派）；有权的 Pro 用户在策略编辑器里获得模型标签页、词汇标签页、结构体 / 别名 / 词汇补全与词汇规范预览。

**Architecture:** cloud 新增两张表（`CapabilityGrant`、`CapabilityTeamAllotment`）与一个代码注册表；`resolveEntitlement` 按「部署前提 → 全局开关 → 套餐 → 授权来源」判定，授权现读不缓存。编辑器页在服务端解析能力后经 props 传入，能力为假时编辑器逐字节不变。aster-lang-ts 提供补全、hover、文档符号与 `aster/canonicalPreview`（以及阶段 2 才用的 `./layout` 子路径），随 eco-1.0.49 之后的下一个车次发 npm；cloud 中**不依赖**新 LSP 的部分先合，依赖的部分在该版本发布后再合。

**Tech Stack:** cloud：Next.js（Cloudflare Workers）、Drizzle + Postgres、vitest（unit / integration PG）、Playwright、next-intl。aster-lang-ts：TypeScript、vscode-languageserver、`node --test`。

**Spec:** `docs/adr/0058-structured-authoring-capability-and-policy-layout.md`（ACCEPTED 2026-11-16，aster-api#551）。本计划只实施 ADR §9.1；§7（LayoutMap 存储与视图）与 §9.3（旧开关迁移）不在本计划内，`./layout` 子路径除外（ADR §9.1 第 3 步要求它随同一 ts 版本发布）。

## Global Constraints

- 能力键 `structured_authoring`；产品名 en「Structured Authoring」、zh「结构化编写」、de「Strukturiertes Verfassen」、hi「संरचित लेखन」（ADR §14.3）。
- `PlatformSetting` 键：`capability.structured_authoring.enabled`（缺行默认 **false**）、`capability.structured_authoring.team_delegation.enabled`（缺行默认 **true**）。
- 套餐：`PlanCapabilities.structuredAuthoring`：free = false；trial、pro、team、enterprise = true。套餐持有人 = `planHolderForTeam(userId, ctx.teamId)`。
- 判定顺序：`unavailable` → `disabled` → `plan_required` → `not_granted`，返回第一处失败；来源之间无优先级（ADR §4.4）。
- 授权、团队成员、额度行一律经 `freshDb` 读（#614）；全局开关经 `getSetting`（60 秒 isolate TTL）；不加跨请求缓存。
- 只有 `Team.ownerId` 能委派，团队 `admin` 不能；委派对象必须是本团队非 viewer 成员；viewer 不享有团队授权与委派，但被暂停的委派仍占座（ADR §4.6）。
- 写接口一律 `requireLicenseWriteOk`；平台接口另加 `requireAdmin`。
- 错误码（JSON `{ error, code }`）：`invalid_payload`(400)、`unknown_capability`(404)、`subject_not_found`(404)、`grant_not_found`(404)、`not_team_owner`(403)、`team_delegation_disabled`(403)、`delegation_not_supported`(400)、`not_team_member`(400)、`viewer_not_eligible`(400)、`seat_cap_reached`(409)、`seat_cap_below_active`(409)。
- 审计 `action`：`capability.grant`、`capability.revoke`、`capability.allotment.update`、`platform_setting.update`（仅 `capability.*` 键）；`revokeReason` ∈ `manual` / `member_removed` / `team_deleted` / `migration`。
- 语言特性（`Define`、`type X as`、`Use … as X`、词汇）与全部 LSP 请求**不设门**（ADR §5.2）；阶段 1 不新增编辑器后端接口（词汇标签页复用现有 `/api/v1/domain-vocabularies/terms`）。
- 能力为假时编辑器 DOM 与今天逐字节一致。
- cloud 迁移拆分：`drizzle/*.sql` 只在**只含迁移**的 PR 中出现（`schema.ts`、`drizzle/meta/`、`src/__tests__/` 可同 PR）；不用 `migration-and-code` 标签；迁移在生产确认应用后才合代码 PR。
- 新文案进 `src/i18n/demo-supplement.ts`（en / zh / de / hi）。代码注释用简体中文。
- 提交信息结尾 `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`；PR 正文结尾 `🤖 Generated with [Claude Code](https://claude.com/claude-code)`。

## Review Focus

1. 两个 owner 会话并发委派最后一个座位：只有一个成功，另一个 409 `seat_cap_reached`（T6 并发测试）。
2. 授予给不存在或已软删除的用户、不存在的团队：404 `subject_not_found`，不留行（T4）。
3. 团队已获团队授权，但本人在该团队是 viewer、或同时是另一已授权团队的 member：前者不命中、后者命中（T3）。
4. 开关 OFF 但用户持有有效授权：编辑器页 props `allowed=false`，DOM 与基线快照一致（T7）。
5. 结构体名与字段名共用同一本地化词（ADR 0051 回归集）时，类型位置只给类型、表达式位置只给对应角色的词汇（T10、T11）。
