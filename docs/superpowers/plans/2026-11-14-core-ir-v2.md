# Core IR v2 实施计划（ADR 0055）

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 两引擎产出同一种 Core IR v2（`schemaVersion: 2`）。v2 由 locales 中的 JSON Schema 定义，所有读方都严格读取；每个语料文件在两引擎下的规范 IR 字节一致（只排除 `origin.*.col` 和登记在案的值层豁免）。

**Architecture:** schema 源放在 aster-lang-locales，core 与 ts 各持副本，由 sibling parity 测试守护。两引擎各自补齐、改正 lowering，并通过同一套 `CanonicalJson` 规则输出字节。aster-lang-test 的门禁从「归一后比较」改为「schema 校验加逐字节比较」。

**Tech Stack:** Java 21 / Jackson / networknt json-schema-validator（core、truffle）；TypeScript / ajv / json-schema-to-typescript / vitest（ts）；Node ≥ 23.6（aster-lang-test）；Quarkus（aster-api）；Next.js（aster-cloud）。

**Spec:** `docs/adr/0055-core-ir-v2.md`。字段取舍以 ADR §4 表为准，本计划只引用其编号（#1–#19），不重复理由。

## Global Constraints

- 项目尚未上线：不写数据迁移，不保留 v1 读方、别名或宽松 mapper。数据靠清库与重建处理。
- `schemaVersion` 是 JSON 整数 `2`（字符串 `"2"` 属于类型错误）。读方遇到缺失或其它值即拒收，aster-api 对应的错误码为 `unsupported_schema_version`（HTTP 400）。
- 所有字段恒输出：标量与对象用 `null`，列表用 `[]`，布尔用 `false`（ADR #19）。
- 规范字节 = core `aster.core.canonical.CanonicalJson` 规则。`Double.value`、`Range.min/max` 是规范十进制串，语法 `^(0|-?[1-9][0-9]*(\.[0-9]*[1-9])?|-?0\.[0-9]*[1-9])$`（全串锚定）（IR 中不允许 `"-0"`；源码 `-0.0` 由 lowering 归一为 `"0"`），由 lowering 从源码字面量经任意精度十进制（Java `BigDecimal`，ts `decimal.js`）求出，不经 double。
- 读入流程固定为：解析为 JSON 树 → 预检查 `/schemaVersion`（缺失、非整数或不为 2 时报 `unsupported_schema_version`）→ 对输入做 JSON Schema 校验 → 严格绑定 → 不变式检查（ADR §5）。
- 跨语言接口对应：Java `CoreIrJson.read` / `serialize` / `validateCoreIrInvariants`，ts `readCoreIr` / `serializeCoreIr` / `validateCoreIrInvariants`，两组语义相同。CLI 的规范字节字段名统一为 `irCanonical`。
- IR 的 Jackson 读方一律 `FAIL_ON_UNKNOWN_PROPERTIES=true`。
- 分支：每个仓的分支都叫 `feat/core-ir-v2`。引擎仓与 aster-lang-test 的 CI 优先检出同名兄弟分支；**aster-api 例外**，它的 CI 只认 `v1.0.46` tag，只在本地组合构建下验证（见「CI 中的兄弟仓检出」）。只做本地合并；按 ADR → plan → SDD 流程执行。
- 所有 IR 整数都是 Int32（ADR §3 `$defs/Int32`，与 Java `int` / `Integer` 一致）；`inputRefs` 是唯一的可空列表。
- 版本：引擎 1.0.46（platform `release-plan.json`），ts npm 2.0.0，aster-lang-test npm 包 major bump（删除 `normalizeIr` 导出）。

## Review Focus

1. **注解参数顺序**：`@control("A")` 写在 `@id("X")` 之前、同一注解有多个位置参数时，两引擎的 `args` 顺序必须都等于源码顺序。由 Task C2 / T2 的 `annotations_preserve_source_order` 与 `annotation_args_preserve_source_order` 覆盖；C3 验证 `Annotation.arg` 的消费方。
2. **中文 / 印地文枚举变体**：`When 拒绝`（变体名没有大小写）必须降级为 `PatCtor`，不能降成 `PatName` 绑定。由 Task T2 的 `cjk_enum_variant_lowers_to_patctor`，加 Task X1 的语料样本覆盖。
3. **浮点字面量**：`0.1`、`1.0`、`1e-7` 的规范字符串两引擎必须一致。由 Task C1 / T1 共用夹具 `double-literals.json` 覆盖。
4. **效应变量与内建效应同名**：`Rule f<IO>` 两引擎必须报同一个诊断码，不能静默当作具体效应。由 Task C4 / T2 的 `effect_param_shadowing_builtin_rejected` 覆盖。
5. **旧 IR 被提交到 `/evaluate-json`**：v1 形状（没有 `schemaVersion`）必须返回 400 `unsupported_schema_version`，不能返回 500，也不能执行。由 Task A1 的 `v1_ir_rejected_with_400` 覆盖。
