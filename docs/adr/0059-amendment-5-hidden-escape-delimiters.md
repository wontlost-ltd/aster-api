## 0. TL;DR

| 主题 | 决定 |
|---|---|
| 能藏什么 | 只能藏 ADR 0064 转义 token 的两个反引号，且只能以**转义三元组**的形状：`` {canonical:"`",display:""} ``、一个内容 span（转义内容，原样显示）、`` {canonical:"`",display:""} ``。每个排版至多 4 组 |
| 不能做什么 | 反引号不能与别的字合进一个结构 span；不能显示成别的字；任何结构 span 的 display 都不能含反引号（防止把关键词伪装成转义名）；名字本身永远不藏 |
| L9 怎么改 | 只免去三元组的两个**内侧**边界；两个外侧边界照旧补空格。由此可证被接受的三元组一定是真转义 token 或整个在注释里，不可能在字符串里（引理 1） |
| 新的编译判定 | **去反引号不变性**：对被隐藏转义的每个非空子集 S，删掉 S 的反引号得到 `C⁻(S)`，它必须编译失败，或与 `C` 的 `positionFreeSha256` 相同（≤ 15 次额外编译） |
| 结论 | 对 canonical 评审者（审批、评审、对比，R15）：隐藏不存在，他们看到带反引号的 `C`。对按平台给出的切分与结构映射阅读的 display 读者：消失的只有定界符，名字每个字照旧可见；把被隐藏的词读成关键词、别名、触发词或字面量，得到的源码要么编译失败、要么同一 IR（定理，§3）。自行猜测结构映射或重新切分的读者不在保证内，补偿沿用修订 4（映射可见） |
| 反向映射 | 隐藏的反引号就是 display 为空的结构 span，D7 原样适用；派生排版再过 L10，失败为 `DISPLAY_REJECTED`；多解照旧 `DISPLAY_AMBIGUOUS`，从不借编译结果挑解 |
| 执行点 | ts `validatePolicyLayout`（平台保存、导出）、core `aster.core.layout` + aster-api（签名前）、两个 CLI（`verify`、`show`、`run --display`），同一组向量 |
| 包格式 | 不升次版本：转义语法与 L10 同列车，「能编译转义的 CLI」恰是「实现 L10 的 CLI」 |

## 1. 问题

ADR 0064 允许 `` `当` `` 这样的转义名。若诗句里的内容词恰好是关键词，canonical 必须写成 `` `当` ``；排版若只能原样显示它，诗句里就多出两个反引号。产品负责人选择允许隐藏它们。

在修订 4 的规则下，隐藏反引号做不到：把反引号切成 `display:""` 的结构 span 后，L9 会在转义内部（反引号与名字之间）补空格，`` ` 当 ` `` 是 `PARSE_INVALID_ESCAPE`，编译失败，L9 拒绝。这是正确的缺省——本修订要在打开这扇门的同时证明它不会成为显示欺骗的通道。

要防的东西只有一类：**角色**。转义内容在内容 span 里原样显示，读者看到的字与 IR 名字逐字相同（ADR 0064 N4）；藏起反引号丢掉的信息只是「这个词是名字」。读者可能把它读成关键词（`当` 读作 WHEN）、别名（`低头` 读作 RETURN）、字面量触发词（`思故乡` 读作 `"静夜思"`）或字面量关键词（`none` 读作空值）。

## 2. 规则 L10

记号：`L` 为合并形态的排版，`C = toCanonical(L)`。span 下标从 0 起。偏移单位与修订 4 §4「共同约定」相同（UTF-16 code unit）。**反引号**指 U+0060。

### 2.1 L10a 形状（不编译；属于 `display` 检查项，与 L1–L7 同列）

1. **display 不含反引号**：任何结构 span 的 `display` 都不含反引号。
2. **反引号结构 span 只有一种形状**：`canonical` 含反引号的结构 span，`canonical` 必须恰为 `` "`" ``，`display` 必须恰为 `""`。
3. **配对**：从左到右扫描 span，遇到未被消费的反引号结构 span `i`（开），要求 `i+1` 是内容 span、`i+2` 是反引号结构 span（闭），三者构成一个**转义三元组**，消费 `i+2`。任何反引号结构 span 不属于恰好一个三元组即失败。
4. **内容**：三元组中内容 span 的 `text` 全由标识符字符类 `[\p{L}\p{M}\p{Nd}_]` 组成（修订 2 R6 已在用的字符类；不含空白、`.`、引号、反引号与私有区字符）。
5. **上限**：三元组至多 **4** 个。
6. 内容 span 里的反引号不受限制：它们是 canonical 原文，原样显示。

### 2.2 L9 的修改（编译；属于 `display-ir`）

对三元组 `k`，记 `o_k` 为开反引号在 `C` 中的偏移，`c_k` 为闭反引号的偏移（`c_k = o_k + 1 + |内容|`）。

- **内侧边界** `o_k + 1` 与 `c_k` 从 L9 的边界集合 B 中**去掉**。
- **外侧边界** `o_k` 与 `c_k + 1` 留在 B 中，照修订 4 L9 原有条件补空格。
- L9 其余部分不变。

### 2.3 L10b 去反引号不变性（编译；属于 `display-ir`）

对三元组集合的每个**非空子集** S（至多 2⁴ − 1 = 15 个），令 `C⁻(S)` 为从 `C` 中删去 `{o_k, c_k : k ∈ S}` 处字符所得的文本。用与 `C` **相同**的编译输入（locale、aliasSet、`allowStructural`、词汇）编译 `C⁻(S)`，要求：

> 编译失败（任何错误级诊断），**或** `positionFreeSha256(C⁻(S)) = positionFreeSha256(C)`。

否则 L10 失败。

### 2.4 失败码

| 执行点 | L10a | L10b |
|---|---|---|
| CLI `verify` | `PKG_DISPLAY_INVALID`（检查项 `display`） | `PKG_DISPLAY_INVALID`（检查项 `display-ir`） |
| CLI `show` / `run --display` 包排版 | `PKG_DISPLAY_INVALID` | `PKG_DISPLAY_INVALID` |
| CLI 派生排版 `L'`（D7） | `DISPLAY_REJECTED` | `DISPLAY_REJECTED` |
| aster-api 签名前（D11） | 省略排版，原因 `display_rules_failed` | 同左 |
| ts `validatePolicyLayout`（平台保存） | `layout_escape_delimiter_invalid` | `layout_hidden_escape_changes_program` |

不新增 CLI 输出码。

## 3. 论证：隐藏的转义改变不了评审者对执行内容的认识

### 3.1 前提

- **P1**（修订 4 L9 的同一前提）：改变一个字符串字面量的值，或把一个名字切开，会使编译失败或改变 `positionFreeSha256`；在 token 边界插入一个空格不改变 IR。两引擎的 IR 已逐字节对齐（ADR 0056、修订 1 A2）。
- **P2**（ADR 0064 N1a）：转义内部不允许空白；开反引号之后到同一行下一个反引号为止是一个转义 token；闭反引号必然紧跟在标识符字符之后。
- **P3**（修订 4 L3）：`toCanonical(L) = C`，内容 span 的字符在 display 中原样出现。
- **P4a**（ADR 0058 §7.1、§7.2，修订 4 D1）：执行只由 `C` 决定；layout 不是编译输入，不进 envelope。策略包的签名**同时**覆盖 `policy/policy.aster`（即 `C`）与 `policy/display/` 两个排版载荷——签名保证它们未被篡改，但排版不因被签名而成为编译身份的一部分。
- **P4b**（ADR 0058 §7.7 第 1、2 条，修订 1 R15）：审批视图、评审面板与版本对比 canonical 优先，显示的是 `C`；diff 以 `C` 为准。
- **P5（实现要求，不是已证前提）**：L10b 对每个变体 `C⁻(S)` 的「编译失败 / 同一 IR」结论在两引擎上必须相同。依据是 ADR 0056 修订 A6（结构关键词作名字两引擎都报错）与 parity 门；共享向量只能**验证**语料内的一致，不能**证明**任意输入的一致。所以执行上要求失败封闭：平台保存与 cloud 导出（ts）和 aster-api 签名前（Java）都跑 L10，两者都通过才进包（D11）；语料外若两引擎结论不同，结果是某一侧拒绝（保存失败、省略排版或某个 CLI 的 `verify` 失败），从不静默接受。

### 3.2 引理 1：被接受的三元组是真转义 token，或整个位于注释里

设 `C` 编译成功，三元组 `k` 通过 L10a 与修改后的 L9。`C` 中位于 `o_k` 的反引号只可能处在四种词法位置（其他位置的反引号是词法错误，`C` 就不会编译）：

1. **字符串字面量内**。内容只含标识符字符，没有任何字符串的闭引号（`"`、`」`、`』`、`»`、`”` 都不是标识符字符），所以 `c_k` 与 `c_k + 1` 仍在同一个字符串内（`c_k + 1` 至多等于闭引号的位置，插在它前面仍在字符串里）。`c_k + 1` 一定被补空格：`C[c_k]` 是反引号而不是换行；它所在的行在它之前含有反引号，不是纯缩进；字符串后面还有闭引号，所以 `c_k + 1 < |C|`。补的空格进入字符串，值改变，由 P1，L9 拒绝。**这一步不依赖字符串是否可以跨行**（ts 词法器允许字符串跨行，`lexer.ts:570-584`），因为用的是外侧的闭边界，不是开边界。
2. **注释内**。注释到行尾为止，内容不含换行，所以整个三元组都在这一个注释里。注释不进 IR，隐藏它的字符不影响执行。允许，无害。
3. **是某个转义的闭反引号**。由 P2，`C[o_k − 1]` 是同一行的标识符字符，所以 `o_k` 既不在文首、也不紧跟换行、也不在行首缩进里，L9 会在 `o_k` 补空格。空格落在那个转义的名字与它的闭反引号之间，由 P2 是 `PARSE_INVALID_ESCAPE`，L9 拒绝。
4. **是某个转义的开反引号**。由 P2，词法器从 `o_k + 1` 读到同一行的下一个反引号；内容不含反引号，`C[c_k]` 是反引号，所以这个转义 token 恰为 `` `内容` ``，两个反引号恰是它的定界符。

所以只剩情形 2 与 4。∎

引理 1 说明了 L9 为什么只免去内侧边界：外侧边界正是把情形 1、3 挡在外面的那两个补空格位置。行首的开反引号（例如 `` `当` `` 作语句的第一个词）会因 L9 的缩进条件而不补 `o_k`，这不影响论证：情形 3 要求前一字符是标识符字符，行首不可能；情形 1 由 `c_k + 1` 挡住。

### 3.3 引理 2：隐藏只去掉定界符，名字与值一个字都不少

由 P3，三元组的内容 span 原样出现在 display 中。由引理 1，被隐藏的字符只是真转义 token 的两个反引号（情形 4），或注释里的两个字符（情形 2）。由 ADR 0064 N4，IR 名字就是内容 span 的文本。L10a 第 1 条禁止任何结构 span 显示反引号，所以 display 中出现的反引号都来自内容 span，也就是 canonical 原文：读者看到的「转义」都是真的。其余结构 span 仍受 L5–L9 约束：三元组的结构 span 只含一个反引号，不含数字、词汇条目、字面量关键词与运算符，L6、L7、L8 对它们自然成立。∎

### 3.4 引理 3：隐藏反引号带来的新读法恰是 `C⁻(S)`，而它们不是另一个程序

**读者模型**。display 读者不是在编译 display 文本；他是在猜「这段显示背后是哪份 canonical」。本修订的保证针对的是**按平台给出的切分阅读**的读者：

- **切分是给出的，不是猜的**。ADR 0058 §7.4 明确拒绝「由 display 文本反推 span」，因为对齐本身有歧义；因此每个显示面都把切分交给读者：平台 display 视图以独立样式渲染结构 span、悬停显示 canonical（§7.7 第 3 条），被隐藏的转义名另有专门样式与悬停（ADR 0058 修订 3 E7）；纯文本包由 `aster show` 在 stderr 打印结构映射（D6）与被隐藏转义的清单（§4.3）。
- 所以读者的一个读法是：**沿用 `L` 的切分与每个结构 span 的 canonical**（二者都由上述显示面给出：结构 span 悬停即见 canonical，`show` 逐条打印 `display ⇐ canonical`），只在自己的理解里决定被隐藏的词各是什么角色；他相信执行的是这个假设对应的 canonical。
- **不覆盖**的读者：无视样式、悬停与 `show` 输出，只拿 display 纯文本自行重新切分、或自行猜测结构 span 背后的 canonical 的人。后一类正是修订 4 残余风险 ①② 描述的读者，修订 4 对它的补偿也正是「把映射给出来」；对这类读者本修订**不作任何声称**——既不说隐藏反引号会加重、也不说不会。对这样的读者，即使没有任何转义，display 文本本来就不决定程序（同一串 display 可由多种切分得到，§7.4 的理由）；本修订既不能也不声称为他提供保证。向量 E21 固定这一边界：它检查的是「切分与标记确实被给出」，不是 L10。

在这个模型下，若读者还尊重被隐藏转义名的标记，他对角色根本没有歧义；以下证明的是更弱的读者——沿用切分、但**忽略**转义名标记、把某些被隐藏的词当裸词读——也读不出另一个程序。

**升程（lifting）**。记 `L_vis` 为把 `L` 的每个三元组合并为一个内容 span（反引号留在内容里）的同一排版，显然 `toCanonical(L_vis) = C`。对三元组的子集 S，记 `L_vis^S` 为从 `L_vis` 中删掉 S 各三元组的两个反引号所得的排版：只改这几个内容 span 的文本，**其余每个 span（包括全部结构 span 及其 display）原封不动**。由于内容 span 在 canonical 与 display 中是同一段文本：

- `toCanonical(L_vis^S) = C⁻(S)`（删掉的正是 `o_k`、`c_k` 处的字符）；
- `toDisplay(L_vis^S)` = 把 `toDisplay(L_vis)` 中 S 的反引号删掉；特别地 `toDisplay(L_vis^{全部}) = toDisplay(L)`。

所以模型内的读者面对 `toDisplay(L)` 时，唯一的自由度是「哪些被隐藏的词其实是裸词」；他认定为裸词的集合 S 恰好把排版假设从 `L_vis` 换成 `L_vis^S`，**切分与全部结构 span（含其 canonical）不变**。也就是说：这样的读者的全部假设空间正是 `{L_vis^S}` 这一族（S 可为空）。

**结论**。模型内读者的每个读法对应的 canonical 恰是某个 `C⁻(S)`（S 为空时就是 `C`）；L10b 对**每一个**非空子集要求 `C⁻(S)` 编译失败或与 `C` 同一 IR：

- 若 `C⁻(S)` 编译失败，这种读法不对应任何程序，读者从中读不出「会执行什么」；
- 若同一 IR，这种读法执行的就是同一个程序。

不存在第三种情况。穷举子集而不只看「全部去掉」，是因为读者可能只把其中一部分当裸词；§6 向量 E5 是「全部去掉编译失败、只去掉一个却编译出另一个程序」的实例。把结构 span 的 canonical 理解错的读者不在模型内（见上），引理 3 对他不作声称。∎

### 3.5 定理

对任何通过 L1–L10 的排版：

1. **执行的程序**只由带反引号的 `C` 决定（P4a）；排版虽在包签名覆盖之内，但不进入编译与 envelope。
2. **canonical 评审者**（审批视图、评审面板、版本对比，P4b）看到的就是带反引号的 `C`，隐藏对他们不存在。
3. **按给出的切分与结构映射阅读的 display 读者**（§3.4 读者模型）看到的名字与值逐字等于 `C` 中的名字与值（引理 2）。记 `L_vis` 为把 `L` 的每个三元组还原为可见内容（反引号留在内容 span 里）的同一排版。`L` 的 display 与 `L_vis` 的 display 只差这些反引号；读者从前者能多出来的读法，只有「把被隐藏的某些词当裸词读」，即某个 `C⁻(S)`；由引理 3，它们要么不是程序、要么是同一程序。

所以：被隐藏的转义不能改变执行的内容（1）；不能改变 canonical 评审者看到的东西（2）；对按给出的切分与结构映射阅读的 display 读者，他可能形成的每一个读法要么不是程序、要么就是执行的程序（3）。本定理**不**覆盖自行猜测结构映射或重新切分的读者（残余风险 ⑥⑦）——结构 span 把关键词显示成别的字本是 ADR 0058 允许的能力，修订 4 以「映射可见」（悬停、`show` 的结构映射）补偿其残余风险 ①②，本修订沿用同一补偿，不另作声称。显示视图仍要给被隐藏的转义名加专门样式与悬停（ADR 0058 修订 3），`show` 在 stderr 列出它们（§4.3），把剩下的「角色猜测」也变成可查证的。

### 3.6 接受的残余风险

| # | 风险 | 为什么接受 / 补偿 |
|---|---|---|
| ③ | 同一段显示里，同一个词既作关键词出现、又作被隐藏的转义名出现（如别名 `低头` 与名字 `` `低头` ``），读者分不清哪个是哪个 | 引理 3 保证不存在另一种可执行的读法；显示视图的转义名样式与悬停、`show` 的 stderr 列表可查证；评审走 canonical。这与修订 4 已接受的残余风险 ①（结构关键词可显示成别的字）同一性质 |
| ④ | L10b 的「编译失败」在两引擎上不一致（parity 缺陷） | 共享向量与 ADR 0056 的 parity 门覆盖语料；签名前 aster-api（Java）跑 L10、cloud 保存与导出（ts）跑 L10，两个都通过才进包（D11）；语料之外两引擎若不一致，结果是某个 CLI 的 `verify` 失败——失败封闭，不会静默接受 |
| ⑤ | 注释里的反引号被隐藏 | 注释不执行（引理 1 情形 2） |
| ⑥ | 读者不看给出的映射、自行猜测某个结构 span 背后的 canonical，同时把被隐藏的词当裸词读 | 不在保证范围：L10b 只检查真实 `C` 的变体，不检查「猜错的映射 + 去反引号」的组合。补偿与修订 4 残余风险 ①② 相同——映射在每个显示面可见（悬停、`show` 的结构映射），被隐藏的转义名另有标记（ADR 0058 修订 3 E7）。向量 E20a / E20b 固定「结构替换 + 隐藏反引号」在模型内的判定 |
| ⑦ | 读者无视样式、悬停与 `show` 输出，只凭 display 纯文本自行重新切分 | 不在保证范围（§3.4 读者模型）：即使没有转义，display 纯文本也不决定程序，这正是 ADR 0058 §7.4 拒绝反推切分、并要求切分可见的原因。E21 检查切分与标记确实被给出 |

## 4. 各执行点

### 4.1 core `aster.core.layout`（D9 增补）

- `hiddenEscapeTriples(layout)`：L10a，返回三元组列表或第一个违例；纯字符串运算。
- `padStructural`：按 §2.2 去掉内侧边界。
- `stripHiddenEscapes(source, triples, subset)`：生成 `C⁻(S)`。
- 编排（编译 15 个变体、比较哈希）在 truffle CLI 与 aster-api，与 L8、L9 同处。

### 4.2 ts

- `./layout` 增加同名函数 `hiddenEscapeTriples`、`stripHiddenEscapes`；`padStructuralSpans` 按 §2.2 修改；`checkPackageLayout` 含 L10a。CLI 在 `src/policy-package/` 编排 L10b。
- **`validatePolicyLayout`（平台保存与 cloud 导出）**：
  - 新码 `layout_escape_delimiter_invalid`（L10a）与 `layout_hidden_escape_changes_program`（L10b）。
  - `layout_structural_hides_value` 的词法启发式（`value-tokens.ts`）把转义 token 看成「名字部分 + 两个定界符」：名字部分必须整个落在一个内容 span 里（与今天对名字 token 的要求相同）；两个定界符只有在形成 L10a 三元组时才允许落在结构 span 里。
  - L10b 需要完整编译输入：`validatePolicyLayout` 增加可选参数 `compileContext`（版本的词汇作用域与 `allowStructural`）。cloud `prepareLayout` 传入版本的编译上下文。**未传入时，含三元组的排版一律以 `layout_hidden_escape_changes_program` 拒绝**（失败封闭）。

### 4.3 CLI（D5、D6、D7 增补）

- `verify`：`display` 检查项含 L10a；`display-ir` 含修改后的 L9 与 L10b。
- `show`：stderr 的结构映射之后，每个三元组一行 `` hidden escape: "`当`" (name) ``（JSON 字符串形式，按出现顺序）。
- `run --display` / `show --from-display`：见 §4.4。

### 4.4 反向映射（D7）怎么处理被隐藏的转义

- **计数不变**：三元组的两个结构 span 是 `display:""` 的结构 span，参与 D7 的「隐藏串」与锚定条件，与隐藏空格完全一样。一段隐藏串可以同时含隐藏空格与隐藏反引号（它们是相邻的独立结构 span）。
- **从不借编译挑解**：解的个数在字符串层面确定，编译只在唯一解之后进行。解 ≥ 2 一律 `DISPLAY_AMBIGUOUS`，即使其中只有一个能编译。理由同 D7：「从不替用户猜」。
- **派生排版过 L10**：唯一解得到 `L'` 后，在修订 4 的「L2、L5、L6、L7」之后跑 L10a（失败 `DISPLAY_REJECTED`）；编译 `C'` 之后，在 L8–L9 之后跑 L10b（失败 `DISPLAY_REJECTED`）。用户把被隐藏的名字改成含空格的文本、改成会被静默改名的词、或改成与字面量同形的词，都在这里被拒。
- **`DISPLAY_AMBIGUOUS` 的典型来源**：用户在被隐藏的名字旁边重复输入了名字的字，原名仍可在多处作锚（§6 R3）。

## 5. 包格式与兼容

- **不升包格式次版本**。带隐藏转义的排版必然对应含转义的源码；转义语法与 L10 在同一列车进入两个 CLI 与 aster-api，所以能编译这份源码的 CLI 一定实现了 L10，锁文件 `packageFormats` 不变。
- 早于该列车、支持 1.1 的 CLI 遇到这样的包：`recompile`、`run`、`show --from-display` 都因词法错误失败（失败封闭）；不带 `--recompile` 的 `verify` 与 `show` 会通过 L1–L7 并显示文本，stderr 的结构映射照旧列出 `` "" ⇐ "`" ``。B 包 README 指向的 CLI 版本来自锁文件，必然支持。
- 不含三元组的排版：L9 的边界集合不变，L10 不产生任何额外编译；全部既有向量与输出逐字节不变。

## 7. 成本

- L10a：线性扫描。
- L10b：至多 15 次额外编译（每次源码 ≤ 12 288 字节，修订 4 L2），只在排版含三元组时发生；`run --display` 对 `L'` 再至多 15 次。上限 4 是为了让穷举子集有界且可预算；放宽需要新修订并附真实诗句的需要与实测耗时。
