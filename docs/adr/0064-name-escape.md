## 0. TL;DR

| 主题 | 决定（一句话） |
|---|---|
| 要解决什么 | 今天没有办法写出一个「与关键词同形的名字」：zh 字段 `版本` 被静默改名为 `version`，de 字段 `wenn` 在 Java 里成了 `If`、在 ts 里是 E055（§1） |
| 不做什么 | **不让编译器读排版**（备忘录方案 (a)）：它会推翻 ADR 0058 §7.1 / §7.2 / §7.7、修订 1 R15 与 0059 A4 D1 / D7 六条已采纳条款，并造出「评审看到 X、运行的是 Y」的缺口 |
| 语法 | `` `名字` ``：一对 ASCII 反引号（U+0060）包住**一个**标识符词素。转义 token **永远是名字**——不是关键词、软关键词、别名、字面量触发词或冠词（§3） |
| 规范化 | 转义段与字符串字面量一样**不透明**：关键词翻译、别名、字面量宏、冠词删除、`customRules`、类型别名改写与各个 transformer 都不碰它（§4） |
| IR | 反引号消失，名字原样保留；对本来就读作名字的词，加不加转义 `positionFreeSha256` 相同（§5） |
| 编辑器 | 作者不手写反引号：表单与快速修复自动插入；本地化关键词照旧经结构 span 显示在英文规范关键词之上（§7，ADR 0058 修订 3） |
| 显示层 | 排版**可以**隐藏一对转义符（诗句保真），但只能用规定形状，并须通过新包规则 **L10**：去掉被藏反引号的任何组合都不得得到另一个能编译的不同程序；审批与评审照旧看带反引号的 canonical（§8，ADR 0059 修订 5） |
| 诊断 | 新增转义格式错误码；关键词误作名字的报错带「改用 `` `x` ``」提示；静默改名先报警告（§9） |
| parity | 结构关键词作名字两引擎都拒绝（Q5，已裁决，ADR 0056 修订 A6）；`version` / `type` / `given` 作成员两引擎对齐（§10） |
| 兼容 | 反引号今天在两引擎都是词法错误（E050 / `Unrecognized character`），所以纯新增：已有源码含义不变，envelope 算法与向量不变（§13） |

## 1. 背景

本节摘自设计备忘录 §1–§3。证据取自 2026-11-22 的 `origin/main`：aster-api `3de8254`、aster-lang-core `d644d1d`、aster-lang-ts `7e9e4c6`、aster-cloud `8ff362c`；实测用已发布的 `@aster-cloud/aster-lang-ts@3.6.0` 与本地构建的 `aster-cli-1.0.54.jar`（附录 A）。

### 1.1 排版是单向的

LayoutMap 是「同一份 canonical 源码的第二种排版，只给人看」（ADR 0058 §7.1）。`PolicyVersion.content` 是唯一的编译输入，layout 不进 `computeSourceEnvelope`（§7.2）；layout 从 canonical 派生，从不由 display 反推（§7.4）；名字与值只能在内容 span 里原样显示（§7.5）；审批视图 canonical 优先（修订 1 R15）；包里的 `layout.json` 签名但不是编译输入（0059 A4 D1）。编译器、签名与评审者都站在 canonical 一侧。

所以「让排版告诉编译器哪个是关键词」等于让同一份 canonical 字节因一份 JSON 旁注而编译成不同程序：审批者在 R15 视图里看到 `允许`，无法知道它是治理效果 ALLOW、控制关键词还是字段名；有库写权限的人改 layout 就能改执行内容（§7.2 的复验只是一致性检测）；`run --display` 的派生程序不签名，角色随内容 span 编辑而失效。这条路否决（§11）。

### 1.2 冲突清单

| # | 类别 | 例 | 今天 | 本 ADR 之后 |
|---|---|---|---|---|
| 1 | 内置本地化关键词（非结构类）作名字 | zh `版本`、`升级`、`允许`、`属于`；de `erlauben`、`gleich`；hi `अनुमति`、`में` | 规范化器全局翻译，IR 名字成了英文关键词（zh 字段 `版本` → `version`）；部分只在一个引擎失败 | 写 `` `版本` `` 得到名字 `版本`；不写转义的报 W802 警告（Q4 决定以后是否升为错误） |
| 2 | 内置结构关键词作名字 | zh `返回`、`如果`；de `bei`、`wenn`、`sei`；hi `जब`、`नियम` | **两引擎分歧**：ts E055；Java 翻译后经 `structKeywordName` 接受，`wenn` → `If` | 两引擎都拒绝（Q5，ADR 0056 修订 A6），提示改用 `` `wenn` ``；写转义即得名字 `wenn` |
| 3 | 多词用户别名 | en `multiplied by` | 含空格，不可能是名字 | 不变 |
| 4 | 汉字单词别名（ADR 0060） | zh `低头` → RETURN | E808 | `` `低头` `` 是名字，E808 跳过转义名（ADR 0060 修订 2） |
| 5 | 本地化类型别名引导词 | zh `类型` | 只在声明句首是关键词（0058 A2 T3） | 不变 |
| 6 | OF 家族关键词 | zh `结果` | 内部私有区标记 U+E000–E003 还原 | 不变；转义不是这个协议，伪造标记照旧拒绝 |
| 7 | 领域词汇术语与关键词同形 | 词汇术语 `版本` 指字段 `version` | 规范化器先把它翻成关键词，词汇救不回来 | `` `版本` `` 是名字，再按 ADR 0051 解析到 `version`（Q6） |
| 8 | 字面量触发词与关键词同形 | 触发词 `返回` | 关键词优先，触发词静默丢弃（R16'） | **不变**：转义让这个拼写可以作名字，但**不**恢复触发词展开（ADR 0060 修订 2） |
| 9 | 大小写变体 | en `Given` 作名字 | 关键词位置读作关键词（A4 §1.1） | `` `Given` `` 在关键词位置也是名字 |

类别 1、2 是今天的缺陷：静默改名与引擎分歧。九类都不是因为缺少**显示**信息，而是 canonical 文本没有说清楚自己是哪种读法。

### 1.3 今天没有任何转义语法

core `AsterLexer.g4` 没有反引号规则，ts `lexer.ts` 的字符分支也没有 `` ` ``。字符串与注释之外的反引号在两引擎都是词法错误：ts E050 `Unrecognized character '`'`，Java `Unrecognized character`（附录 A）。这让反引号成为一个**免费且向后兼容**的定界符。

## 2. 目标与非目标

- **目标**：一种写在 canonical 源码里、在所有引擎、CLI 与策略包中含义相同的写法，表示「这个词是名字」；编辑器自动生成它；显示层在严格条件下可以隐藏它的定界符。
- **非目标**：
  - 强制「关键词」读法（今天已有：写 en-US 规范关键词，ADR 0060 修订 1 §2.2 第 4 项保证它在所有 locale 都是关键词）。
  - 恢复被 R16' 丢弃的字面量触发词。
  - 改变 IR 名字的生成规则或已存策略的运行时输入键。
  - 任何「编译器读排版」的机制。

## 3. 语法

### 3.1 词法

```
EscapedName ::= "`" NameLexeme "`"
NameLexeme  ::= 一个 IDENT 或 TYPE_IDENT 词素（忽略关键词性），同一行内
Qualified   ::= `a`.`b`        -- 每段各自转义；也可只转义其中一段：s.`版本`
```

| # | 规则 |
|---|---|
| N1 | 转义 token **永远是名字 token**：不是关键词、软关键词、别名、字面量触发词或冠词。token 类（IDENT / TYPE_IDENT）按首字符决定，与不转义时完全相同（core `AsterLexer.g4:204-217`：CJK 与大写拉丁首字符为 TYPE_IDENT，小写拉丁、`_` 与天城文为 IDENT） |
| N1a | 定界符只有 U+0060。转义内容不得为空，不得含空白、换行、`.`、引号、反引号、私有区标记（U+E000–E003）或任何不属于标识符续字符的字符；违反者报新的 `PARSE_INVALID_ESCAPE`（§9）。全角 `｀`（U+FF40）与其他形似字符照旧是 E050（Q2） |
| N1b | 转义自身定界：前后不需要空白。`` 床前`当`明月光 `` 与 `` 床前 `当` 明月光 `` 都是三个 token |
| N1c | 字符串字面量与注释里的反引号只是字符，不是转义 |

### 3.2 两个引擎的词法实现

- **core**：在 `AsterLexer.g4` 增加转义规则，lexer action 按首字符把 token 类型设为 IDENT 或 TYPE_IDENT，文本去掉反引号，并在自定义 token 上置 `escaped` 标志（`AsterCustomLexer` 已有自定义 token 先例）。不用单独的 token 类型：文法里所有接受名字的位置不必改。
- **ts**：`lexer.ts` 增加 `` ` `` 分支，产出 IDENT / TYPE_IDENT，`value` 为去掉反引号的文本，token 带 `escaped: true`。
- 两侧都在词法阶段完成 N1a 的检查，报同一诊断码与同一位置（共享夹具）。

### 3.3 解析器

| # | 规则 |
|---|---|
| N3 | 转义 token 被**所有**关键词判定排除：core 的 `structKeywordName` 软关键词、A4 §1.1 的大小写不敏感语义谓词、0058 A2 T3 的声明句首判定；ts 的 `ctx.isKeyword` 与上下文关键词模型。所以 `` `Given` `` 在关键词位置也是名字，`` `类型` `` 在声明句首也是名字 |
| N3a | 转义名可出现在**任何**接受名字的位置：字段、形参、局部变量、类型名、类型引用、函数名、成员访问、枚举成员、模式里的绑定。不扩大名字可出现的位置 |

## 4. 与规范化、关键词翻译、别名、词汇、字面量宏的配合

| # | 规则 |
|---|---|
| N2 | 规范化器把转义段当作**不透明片段**，与字符串字面量同等对待：不做关键词或别名翻译、不展开字面量宏、不删冠词、不跑 `customRules`（de `oe → ö`）、不做类型别名改写（core 步骤 7.9）、不跑任何 transformer（`result-is` 等）、不做空白归一。两引擎都复用已有的字符串分段器（core `Canonicalizer`，ts `canonicalizer.ts:768-790`），把「反引号到下一个反引号（同行）」加为一种不透明片段 |
| N2a | 不透明片段的识别只看字符：字符串与注释之外，同一行内从 `` ` `` 到下一个 `` ` ``。未闭合的反引号不形成片段，交给词法器报 `PARSE_INVALID_ESCAPE` |
| N2b | 私有区标记协议（类别 6，core `Canonicalizer.java:108-131`）不变；转义片段里出现 U+E000–E003 由已有的 `rejectForgedMarkers` 拒绝（审计 #58） |
| N5 | 名字解析（ADR 0051）不变：转义名与普通名字一样按角色对词汇解析（Q6 推荐「是」）。转义只去掉关键词性，不绕过词汇 |
| N6 | E808（ADR 0060 §5.3 第 2 项）跳过转义名：转义名按构造就是显式的名字。详见 ADR 0060 修订 2 |
| N7 | 别名与词汇校验器（core `UserAliasValidator` / `IdentifierMapping`，ts `alias-validate.ts` / `validateVocabulary`，cloud）拒绝含 U+0060 的别名与词汇 `localized`、`aliases`；字面量宏的**值**可以含反引号（它在字符串里）。详见 ADR 0060 修订 2 |
| N7a | 字面量触发词：转义的触发词拼写是名字，**不展开**。这让名字可以与触发词同形，但不恢复被 R16' 丢弃的触发词；R16' 不变 |

**举例**（canonical 源码 → IR 名字；「今天」一栏取自附录 A）：

```
zh-CN  定义 软件 包含 `版本` 作为 整数。        -- 字段 版本   （今天：静默成 version）
zh-CN  规则 取值 给定 `如果` 作为 整数，…       -- 形参 如果   （今天：ts E055 / Java If）
zh-CN  （aliasSet RETURN=低头）给定 `低头` 作为 整数 -- 形参 低头 （今天：E808）
de-DE  Definiere Antrag mit `wenn` als Int.      -- 字段 wenn   （今天：ts E055 / Java If）
de-DE  Definiere Antrag mit x als `Der`.         -- 类型引用 Der（今天：作冠词删掉）
hi-IN  परिभाषित Software सहित `अनुमति` रूप में Int. -- 字段 अनुमति（今天：allow）
en-US  Rule f given `type` as Int, produce Int:  -- 形参 type   （今天：Java 语法错误）
en-US  Return s.`Given`.                         -- 成员 Given
```

**转义做不到的**：它不能强制关键词读法（写 en-US 规范关键词）；它不能隐藏任何东西（它是 canonical 里可见的文本）；它不能制造新的值（只能命名本来就能命名的东西）。

## 5. IR

| # | 规则 |
|---|---|
| N4 | IR 中的名字是转义内容本身，不含反引号；IR 不记录「是否转义」。对一个不转义也读作同一名字的词，`` `x` `` 与 `x` 的 Core IR `positionFreeSha256` 相同，只有 `origin` 的列号不同（ADR 0037：contentHash 不含 origin） |
| N4a | 词汇解析之后，IR 的 `written` 是转义内容、`name` 是解析结果（ADR 0051 §7 原样） |
| N4b | Core IR schema、`positionFreeSha256` 算法与 envelope 算法都不变；转义只改变 `content` 的字节，因而改变 envelope **值**，算法与共享向量 `envelope-vectors.json` 不动 |

## 6. 格式化器、LSP 与语义高亮

- **格式化器**（ts `formatter`）：保留作者写的每一个转义，包括冗余转义（Q7 推荐不去掉：它让名字不怕将来词法表增长，如 0058 A2 的 `类型`）。从 AST 重新打印名字时，凡是不转义就会被读作关键词、别名、触发词或冠词的名字（按版本的有效词法表与 aliasSet），**必须**加转义；否则格式化会改变程序。格式化前后 `positionFreeSha256` 相同，作为格式化测试的断言。
- **LSP**：
  - 语义 token：转义名按其名字角色着色（变量、字段、类型），并带修饰符 `escaped`；反引号本身按标点着色。不依赖排版，磁盘文件与编辑器结果一致。
  - hover：转义名显示「转义名字：`x`（名字，不是关键词）」。
  - 快速修复「用作名字」：挂在 §9 的关键词误作名字错误、W802 静默改名警告与 E808 上，把该词改为 `` `x` ``。
  - `aster/canonicalPreview`（ADR 0058 §8.2）照常输出，转义名在预览中保留反引号。
- **补全**：在名字位置补全一个与关键词同形的已声明名字时，插入转义形式。

## 7. 编辑器：自动插入转义（方案 (b)）

规则正文见 [ADR 0058 修订 3](0058-amendment-3-editor-name-escape.md)。要点：

- 表单生成器（cloud `source-builders.ts`）在 `fieldNameRoundTrips` / `structNameRoundTrips` 因关键词性失败时生成 `` `版本` ``，界面原因从「保留字」改为「已自动转义」。
- 关键词一侧维持今天的做法：作者想让一个本地化词读作关键词而它有歧义时，编辑器写 en-US 规范关键词，用结构 span 显示本地化词。
- 排版里的反引号默认可见（在内容 span 中，样式淡化）。作者可以显式选择隐藏一对转义符，受 L10 约束（§8）。
- **排版从不携带 token 角色**：layout schema 不变，没有 role 字段。

## 8. 显示层可以隐藏转义符（产品负责人裁决 Q3）

产品负责人选择「允许隐藏」，以保住诗句原文（ADR 0060 §8《静夜思》式的策略里，一个内容词恰好是关键词时）。规则正文是 [ADR 0059 修订 5](0059-amendment-5-hidden-escape-delimiters.md) 的 **L10**，平台保存（ts `validatePolicyLayout`）、导出（cloud、aster-api）与两个 CLI 用同一条规则与同一组向量。这里只给结论：

1. **形状**：一对转义符只能以「转义三元组」隐藏——结构 span `` {canonical:"`", display:""} ``、恰好一个内容 span（转义内容，原样显示）、结构 span `` {canonical:"`", display:""} ``。结构 span 的 canonical 一旦含反引号，就必须恰好是一个反引号并属于某个三元组；不能把反引号与空格或关键词合进同一个结构 span，也不能把它显示成别的字。每个排版至多隐藏 4 对。
2. **真转义**：L9 的补空格照旧作用于三元组的两个**外侧**边界，只免去两个内侧边界。由此可证每个被接受的三元组要么是一个真正的转义 token，要么整个位于注释里；不可能藏在字符串字面量里（ADR 0059 修订 5 引理 1）。
3. **去掉反引号不得得到另一个程序**：对被隐藏转义的每一个非空子集 S，把 S 的反引号从 canonical 中删掉得到 `C⁻(S)`；`C⁻(S)` 必须编译失败，或与 `C` 的 `positionFreeSha256` 相同。读者在显示中看不到反引号，最多会把这个词当成关键词、别名、触发词或字面量；这条规则保证，按平台给出的切分与结构映射阅读的读者，那样读出来的要么不是程序、要么就是执行的程序；自行猜测结构映射的读者不在保证内，补偿沿用 0059 修订 4（映射在每个显示面可见）。
4. **canonical 优先不变**：审批、评审与版本对比显示带反引号的 canonical（ADR 0058 §7.7 第 1、2 条，修订 1 R15）；执行只由 canonical 决定，排版不是编译输入（包签名覆盖排版载荷，但不使它成为编译身份，0059 修订 4 D1）。显示视图对被隐藏的转义名用专门样式并在悬停时给出 `` `x` ``；`aster show` 在 stderr 列出每个被隐藏的转义。
5. **反向映射**：隐藏的转义符就是 display 为空的结构 span，D7 的锚定条件原样适用；派生排版 `L'` 再过 L10，失败为 `DISPLAY_REJECTED`；多解照旧 `DISPLAY_AMBIGUOUS`，不借编译结果挑解。

后果：今天会被静默改名的词（类别 1，如字段 `版本`）**不能**隐藏转义——去掉反引号后它编译成字段 `version`，是另一个程序。Q4 若把静默改名升为错误，这些词随之可以隐藏。结构关键词（类别 2，如诗句里的 `当`）在 Q5 裁决落地后，去掉反引号即编译失败，可以隐藏。

## 11. 考虑过的方案

| 方案 | 结论 |
|---|---|
| (a) 排版标注 token 角色，编译器读取 | **否决**：canonical 不再决定含义（R15 审批者分不清名字与关键词）；layout 要进 envelope，否则审批绑定失效，且推翻 0059 A4 D1；角色偏移要在约十个会移动文本的规范化步骤之后两引擎一致；`run --display` 新增歧义；L1–L9 需要依赖词法器的规则，正是 A4 §5 拒绝的耦合 |
| (a′) 角色放进 envelope 内的签名旁注 | **否决**：修好了完整性一半，修不了评审一半——审批者读的文本含义仍取决于看不见的数据 |
| (b) 只做编辑器辅助 | 关键词一侧今天已能做；名字一侧没有可生成的东西，只能拒绝或改名。须与 (c) 一起做 |
| (c) 语言内转义 | **采纳**（本 ADR） |
| (d) 只改诊断与 parity | 采纳为**前置部分**，但单独不够：类别 1 的「看到 `版本`、运行键是 `version`」仍在 canonical 里 |
| (e) 更多上下文关键词 | 开放（Q8）：每个词要在两引擎各做一份文法工作，而探针显示两引擎恰在这些位置不一致；等 G2 量化后再定 |
| (f) 词法表改名（如 zh IMPORT_VERSION `版本` 改为更长的词） | 只作最严重个例的补充，需门禁扫描；不是通用答案 |
| (g) 模块级「名字」指令（`名字：版本、升级。`） | **否决**：远距离生效，第 80 行的读者看不出 `版本` 为什么是名字 |

| 其他定界符 | `「」『』` 是字符串定界符，`@` 是注解；反引号已由两引擎实测为空闲（附录 A 末行），又是业界惯例（Kotlin、Swift、Scala）。其他候选未逐一实测，不选 |

## 13. 迁移与向后兼容

- **纯新增**：反引号今天在字符串与注释之外是词法错误，G1 = 0 时没有任何已存源码的含义改变。envelope、Core IR schema、`positionFreeSha256` 算法与共享向量都不变；引擎升级照常改变 `toolchainId`，编译缓存随 pin bump 失效。
- **旧引擎**：带转义的源码在旧 CLI、旧 aster-api 上以词法错误失败，不会被误读。
- **回滚**：一旦有版本存了转义，aster-api 与 cloud 的引擎不可回退到 N+1 之前；回退前用 G1 统计受影响版本数。cloud 开关关闭只停止**生成**转义，已存版本照常编译。
- **Q5 的收紧**是行为变化，单独以 G3 把关（ADR 0056 修订 A6）。
- **W802** 只是警告，不改变任何 IR。

### 14.2 仍开放（附推荐）

| # | 问题 | 推荐与理由 |
|---|---|---|
| Q2 | 定界符：只用 ASCII `` ` ``，还是也收全角 `｀`（归一化） | **只用 ASCII U+0060**。① 隐藏已获准，诗句里看不到定界符，全角的美观理由消失；② 归一化是规范化器里一次看不见的改写，正是显示欺骗要避免的那类东西；③ 单一码点让 L10 的字符串检查只有一种形状，形似字符（`´`、`ˋ`、`‘`、`｀`）一律是词法错误；④ 作者不手写转义（编辑器与快速修复插入），而 zh 输入法在该键位通常打出 `·`，全角也并不更顺手。全角 `｀` 保持 E050，并给出「改用 ASCII 反引号」的帮助行 |
| Q4 | 内置关键词作名字的静默改名警告（W802）以后是否升为错误 | **是，分两步**：N 列车只报警告；G2 显示生产命中为 0（或已逐一迁移）、转义已上线并经过一个列车之后，再以独立修订升为错误。升错误还会扩大可隐藏转义的范围（§8）。不推荐改为「IR 保留源码写法」：那会改变已存策略的运行时输入键 |
| Q6 | 转义名是否仍走词汇解析 | **是**（N5）。转义只回答「这是不是关键词」，不回答「这个名字指什么」；保留词汇解析才能救回类别 7（词汇术语 `版本` 指字段 `version`）。显示与评审照旧经 §8.2 词汇规范预览看到解析结果 |
| Q7 | 格式化器是否去掉冗余转义 | **不去掉**。冗余转义让名字不怕将来词法表增长；去掉它会让「今天冗余」的转义在下次加关键词时变成改名。格式化器只**添加**必需的转义（§6） |
| Q8 | 高冲突词（zh `版本`、`升级`、`允许`；en `version`）是否改成上下文关键词 | **暂不，等 G2**。有了转义与编辑器自动插入，作者已不必手写；上下文关键词每个词都要两引擎各做文法工作，而两引擎恰在这些位置分歧。G2 若显示某个词在生产里大量出现在名字位置，再对该词单独立修订（参照 0058 A2 T3） |
