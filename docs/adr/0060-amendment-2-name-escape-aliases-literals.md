## 1. 裁决

| # | 裁决 |
|---|---|
| X1 | **E808 跳过转义名**：名字守卫只检查未转义的名字。`` `低头` `` 是作者显式写出的名字，不与别名 `低头` 冲突。未转义的名字照旧按 §5.3 第 2 项检查，E808 的帮助行增加「或写 `` `低头` `` 作名字」 |
| X2 | **别名与词汇不得含反引号**：别名校验器 v2（core、ts、cloud）拒绝含 U+0060 的别名；词汇校验器拒绝 `localized` 与 `aliases` 含 U+0060 的条目（全部 kind）。字面量宏的**值**可以含反引号：它展开在字符串里（修订 1 R18 的转义规则照旧） |
| X3 | **转义的触发词拼写是名字，不展开**：`` `思故乡` `` 是一个名为 `思故乡` 的名字，即使词汇里有触发词 `思故乡`。这让名字可以与触发词同形 |
| X4 | **转义不解决字面量触发词与关键词的冲突**：R16' 不变——与关键词同形的触发词仍在建作用域时被丢弃，写 `` `返回` `` 得到的是名字 `返回`，不是触发词 `返回` 的展开值。要让那个值出现，作者照旧写字符串字面量 |
| X5 | 别名与关键词同形的规则（§5.3「别名 ≠ 规范拼写」）、`embedded_vocabulary_shadows_keyword`（§6.4）不变：转义只作用于名字，不让别名或词汇条目「借转义」与关键词同形 |

## 2. 说明

### 2.1 为什么 X1 不削弱 §5.3 的安全目的

§5.3 第 2 项（ADR 0022 §11.5 H3 的延续）防的是：一个单字别名恰好与某个名字同形，读者看到 `低头` 不知道是 RETURN 还是名字。转义名在 canonical 中带反引号，审批与评审视图里一眼可辨；显示层若隐藏它，须过 [ADR 0059 修订 5](0059-amendment-5-hidden-escape-delimiters.md) 的 L10（去掉反引号后 `低头` 读作 RETURN，必须编译失败或同一程序，见该修订向量 E17）。

### 2.2 为什么 X2 需要

若别名本身含反引号，`` `低头` `` 既可能是转义名，也可能是一个名为「`` `低头` ``」的别名；规范化器的不透明片段识别（ADR 0064 N2a）只看字符，必须保证没有别名或词汇条目会被一个转义片段整体覆盖。G4 扫描（ADR 0064 §12.1）确认生产里没有这样的条目。

### 2.3 X4：设计备忘录的更正

设计备忘录初稿称转义「解决」类别 8（字面量触发词与关键词同形）。Codex 第一轮评审指出这是过度声明，备忘录已更正，本修订按更正后的结论写：转义让触发词的**拼写**可以用作名字，但不恢复被 R16' 丢弃的**展开**。原因是两者问的问题不同——转义回答「这个词是不是关键词」，R16' 回答「同形时触发词还展不展开」；把转义解释为「强制展开」会让一个名字在不同词汇下变成字符串，正是 L10 要防的角色变化。

## 3. 门禁

- G4（ADR 0064 §12.1）：aliasSet 别名与词汇 `localized` / `aliases` 含反引号，预期 0；不为 0 时 X2 的拒绝只在**下次保存**生效（同 §5.3 的既有做法），已存版本按规范化器的不透明片段规则读，并在扫描报告中逐条登记。
- X1 是放宽（此前 E808 失败的源码不会出现转义，转义此前是词法错误），不需要扫描。

## 4. 共享夹具

aster-lang-test：E808 对转义名不触发、对未转义名照旧触发；E808 帮助行；含反引号的别名与词汇条目被两引擎校验器拒绝；`` `思故乡` `` 与触发词 `思故乡` 并存时为名字；与关键词同形的触发词（zh `返回`）在 R16' 下照旧被丢弃，`` `返回` `` 为名字。
