# ADR 0051 修订 1：类型别名右侧按 TYPE 位置解析，未知类型报 E800（启用 R58 第 1 条）

- 状态：**ACCEPTED**（2026-11-20，产品负责人采纳 eco-1.0.53 Wave B 计划「待裁决」第 8 项的推荐方案）；**实现延后**（1.0.54 或之后），以门禁扫描为前提
- 日期：2026-11-20
- 修订对象：[ADR 0051](0051-position-aware-vocabulary-resolution.md) §5 TypeAlias 行（「TypeAlias 的右侧按 TYPE 递归」）与 §16.3 R58 第 1 条（「延后实现」）
- 相关：aster-cloud/aster-lang-test#174 第 5 项

---

## 1. 现状

§5 与 R58 第 1 条都规定类型别名右侧按 TYPE 位置解析，但两引擎都没有实现：ts `resolve-declarations.ts` 的 `declareTopLevel` 只登记别名的名字、丢弃右侧；core `DeclarationResolver` 原样透传。所以 `Type Amount as Unbekannt.` 在两引擎都编译通过，没有任何诊断（2026-11-20 复核仍如此，两引擎同 pf）。悬空的别名在 IR 里静默保留。

## 2. 裁决

1. 类型别名右侧按 TYPE 角色走 §6.2 的引用解析（递归到泛型参数、`Maybe` / `Option` / `Result` / `List` / `Map` 的元素与键值、函数类型的参数与返回类型），候选来源与其他 TYPE 位置相同：源码声明（含其他类型别名）、词汇 types、内置类型。
2. 右侧的未知类型报 **E800**，报在该名字上，与其他 TYPE 位置同码同参数。
3. 本地化写法解析为规范名，写回别名的右侧（core 写回 `alias.type()`；ts 的 `typeAliases` 改为保留 `{ name, type }`），使用别名的位置据此得到展开后的类型。
4. 别名之间的循环引用另申请新码（R58 第 1 条原文），不在本修订。

## 3. 这是收紧

此前静默通过的悬空别名会变为 E800。实现前必须先跑门禁扫描：导出生产策略源码，找出类型别名声明（引导词 `Type` / `type`，以及修订后的 `类型` / `Typ` / `प्रकार`；`as` 在各 locale 的拼写为 `作为` / `als` / `रूप में`）中右侧不能解析的名字；预期 0 命中。命中的策略由作者改正右侧或删除别名后重新发布，全部处理完再发版。

## 4. 落地

ADR 修订先合（本文件）；引擎实现排在 1.0.54 或之后，core + ts 同名分支，aster-lang-test 同批加正例（右侧为本地化名 → 规范名）与 `tier1-reject` 负例（`expectCode: E800`）。门禁扫描的正则与结果随实现 PR 给出。
